# راهنمای استقرار روی Railway — ربات چت ناشناس نسخه ۲.۴.۰

این پکیج کامل و آماده‌ی دیپلوی است: کد پچ‌شده ۲.۴.۰ + همه فایل‌های پیکربندی Railway.

## محتویات پکیج

| فایل | نقش |
|---|---|
| `bot.py` | کد کامل ربات با پچ جامع ۲.۴.۰ (لیست فحش ۷۵۲ موردی، دستورات متنی مالک با هدف‌یابی ریپلای، تغییر دستی کد مالک، جابجایی «ردیف اول» و…) |
| `Dockerfile` | **روش دیپلوی پیش‌فرض این پکیج** — ایمیج python:3.12-slim + نصب وابستگی‌ها + چک سلامت هنگام بیلد (خط `BUILD-CHECK`). با این فایل، بیلدر (Railpack/Nixpacks) دیگر حدس نمی‌زند؛ همه‌چیز قطعی است |
| `requirements.txt` | وابستگی‌ها: `python-telegram-bot>=22.8,<23` و `jdatetime>=5.0,<7` |
| `railway.json` | فقط تنظیمات دیپلوی: سیاست ری‌استارت ON_FAILURE (۱۰ بار) + `numReplicas: 1` (الزامی — بیش از یک نسخه، دیتای JSON را خراب می‌کند). نه builder دارد نه buildCommand تا با Dockerfile تداخل نکند |
| `Procfile` | دستور start پشتیبان (اگر railway.json را حذف کنید) |
| `.python-version` | قفل پایتون روی 3.12 (محیط تست‌شده) |
| `env.example` | فهرست متغیرهای محیطی لازم با توضیح فارسی |
| `CHANGELOG_v2.4.0.md` | شرح کامل تغییرات این نسخه |

## مراحل دیپلوی (۵ دقیقه)

1. **ساخت سرویس**: در Railway پروژه جدید بسازید و محتویات همین پکیج را در ریشه ریپازیتوری/آپلود قرار دهید. Railway با دیدن `Dockerfile` آن را می‌سازد؛ در لاگ بیلد باید خط `BUILD-CHECK telegram 22.8 | jdatetime ...` را ببینید که یعنی کتابخانه‌ها واقعاً نصب شده‌اند.
2. **Volume (بسیار مهم)**: سرویس → `Settings` → `Volumes` → یک Volume بسازید با **Mount path = `/data`**. همه دیتا (کاربران، چت‌ها، پنل) در JSON روی همین مسیر ذخیره می‌شود؛ بدون Volume با هر ری‌استارت همه‌چیز پاک می‌شود.
3. **متغیرهای محیطی**: سرویس → `Variables` → دو متغیر الزامی:
   - `BOT_TOKEN` = توکن ربات از @BotFather
   - `OWNER_ID` = شناسه عددی تلگرام شما (از @userinfobot)
   - (`DATA_DIR` لازم نیست؛ پیش‌فرض همان `/data` است.)
4. **Deploy** → لاگ‌ها را چک کنید؛ پیام «شروع ربات چت ناشناس | DATA_DIR=/data | OWNER_ID=تنظیم‌شده» یعنی بالا آمده.
5. در تلگرام به ربات `/start` بدهید و با `/panel` پنل مالک را باز کنید.

## نکته‌های عملیاتی

- **ربات Long Polling است** (نه وب‌سرویس)؛ HTTP endpoint ندارد و Healthcheck لازم نیست. اگر Railway پورت خواست، در تنظیمات Healthcheck چیزی تنظیم نکنید.
- **ری‌استارت خودکار**: سیاست `ON_FAILURE` تا ۱۰ بار؛ کرش‌های لحظه‌ای خودشان برمی‌گردند.
- **آپدیت نسخه بعدی**: فقط کافی است `bot.py` جدید را جایگزین کنید و دوباره Deploy — ساختار فایل‌های `/data` سازگار می‌ماند و بکاپ‌های قبلی بازیابی می‌شوند.
- **بکاپ**: از پنل مالک ← «مدیریت بکاپ» می‌توانید فایل JSON را دانلود کنید (بکاپ خودکار پیش‌فرض خاموش است تا حجم دیسک مصرف نکند).
- **فایل‌های دیتا**: `data.json`، `messages/*.json` و بکاپ‌ها همگی زیر `/data` هستند.

## آزمون محلی (اختیاری)

```bash
pip install -r requirements.txt
BOT_TOKEN=1:test OWNER_ID=1 python tests_bot.py   # اگر tests_bot.py را کنار bot.py گذاشته باشید: ۱۹۶ تست
BOT_TOKEN=... OWNER_ID=... python bot.py          # اجرای واقعی
```
